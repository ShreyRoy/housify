# Personal MVP: API policy considerations

Reviewed 2026-11-16. This implementation is a technical integration for the user's explicitly requested personal local workflow, **not Spotify approval or a finding of compliance**. Personal/non-commercial use does not itself resolve the restrictions below.

- [Spotify Developer Policy](https://developer.spotify.com/policy) III.13 restricts analysis of Spotify Content; III.9 restricts transfers with an exception for user transfers of personal/playlist metadata; III.5 addresses integration with another service's content. Whether this metadata enrichment/classification workflow is permitted remains unresolved. The rule-based implementation avoids AI/ML ingestion, but that alone does not settle the other clauses.
- [Spotify Developer Terms](https://developer.spotify.com/terms), especially II.8, IV.2.5, IV.3 and V, cover metadata, third-party transfers, caching, privacy and deletion. Matching sends Spotify-sourced titles/artists and available ISRCs to MusicBrainz. No Spotify access/refresh tokens, artwork, audio, account identity or playlist membership is sent to MusicBrainz. User authorization to implement this is not a representation of provider authorization. Review/clarification is needed before broader use or distribution.
- [MusicBrainz API](https://musicbrainz.org/doc/MusicBrainz_API) and [rate limits](https://musicbrainz.org/doc/MusicBrainz_API/Rate_Limiting) require at most one request per second and an identifying User-Agent. This local process uses `Housify/0.1.0 (https://github.com/ShreyRoy/housify)` and spaces every request/retry by at least 1.1 seconds. Multiple local processes sharing an IP would need coordination; this is not a distributed service.
- [MusicBrainz supplementary data](https://musicbrainz.org/doc/MusicBrainz_Database), including genre/tag associations, uses CC BY-NC-SA 3.0. Attribution and source links are displayed. The implications for redistributing derived classifications or commercial use need separate review. No claim of perfect match or genre accuracy is made.

The initial fixture-only gate has been replaced at the user's instruction. There is no hidden mock fallback in live analysis: absent or failed evidence stays Iffy House with its reason. `/analysis-lab` remains explicitly fictional. No Spotify playlist write endpoints, audio downloads, audio features or AI models are used.
